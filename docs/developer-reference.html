Inicio Rápido

1. Base de datos

# Crear contenedor
docker run -d \
  --name postgreszh \
  -e POSTGRES_PASSWORD=zhin@2024 \
  -p 5435:5432 \
  postgres:16

# Verificar
docker ps --filter "name=postgreszh"

2. Backend

# Migraciones
cd backend/src
dotnet ef database update \
  --project ERP.Infrastructure \
  --startup-project ERP.API

# Correr API
dotnet run \
  --project ERP.API \
  --launch-profile http

API: localhost:5003   Swagger: /swagger

3. Frontend

# Solo primera vez
cd frontend
npm install

# Dev con HMR
npm run dev

App: localhost:5173

El proxy Vite reenvía /api/* al puerto 5003. No hay CORS en dev.

Primer usuario de prueba

# 1. Crear tenant
curl -X POST http://localhost:5003/api/tenants \
  -H "Content-Type: application/json" \
  -d '{"name":"Mi Empresa","slug":"mi-empresa"}'

# 2. Registrar admin (usar el id retornado)
curl -X POST http://localhost:5003/api/auth/register \
  -H "Content-Type: application/json" \
  -d '{"firstName":"Admin","lastName":"ERP","email":"admin@test.com","password":"Admin1234!","tenantId":"<id>","role":"Admin"}'

# 3. Abrir http://localhost:5173 e ingresar con el tenantId, email y password

Flujo de Autenticación

POST /api/auth/loginemail + password + tenantId
→
JwtServiceGenera JWT con claims
→
Zustand authStoreGuarda en localStorage
→
Axios interceptorAuthorization: Bearer <token>
→
API verificaJWT + permisos + token_type

Claims del JWT

ClaimDescripción
subUser ID (Guid)
emailEmail del usuario
tenant_idID del tenant activo
full_nameNombre completo
roleAdmin / SuperAdmin / User
token_typesession / bootstrap
permLista de permisos (multi-value)

Tipos de token

session — Token normal post-login. Acceso completo según permisos del perfil asignado.

bootstrap — Token de setup inicial. Solo permite endpoints de configuración de primer uso. No puede acceder a endpoints de negocio.

El TokenTypeHandler rechaza tokens bootstrap en endpoints de operación normal con 403 Forbidden.

Aislamiento Multi-Tenant

JWT claimtenant_id
→
CurrentTenantServicepropiedad TenantId
→
ErpDbContextpropiedad CurrentTenantId
→
EF CoreWHERE TenantId = @id en toda query

Filtro automático por IMustHaveTenant

Cualquier entidad que implemente IMustHaveTenant recibe el filtro en OnModelCreating automáticamente. No hay que registrarlo manualmente.

// ErpDbContext.cs
foreach (var entityType in
         modelBuilder.Model.GetEntityTypes())
{
  if (!typeof(IMustHaveTenant)
         .IsAssignableFrom(clrType)) continue;
  // aplica: e => e.TenantId == CurrentTenantId
  modelBuilder.Entity(clrType).HasQueryFilter(lambda);
}

Propiedad lazy — crítica

Debe ser una property (no campo), para que EF Core la evalúe en cada query y no en tiempo de compilación del modelo.

// ✅ Correcto: evalúa POR request
private Guid CurrentTenantId
  => _currentTenant.TenantId;

// ❌ Bug clásico: captura valor una vez
var tenantId = _currentTenant.TenantId;
// → todos los queries usan Guid.Empty

Servicios del Frontend

Instancia Axios — lib/api.ts

const api = axios.create({
  baseURL: import.meta.env.VITE_API_URL
  // .env.development → VITE_API_URL=''
  // → /api/* resuelto por Vite proxy a :5003
});

// Inyecta JWT en cada request
api.interceptors.request.use(config => {
  const { token } = authStore.getState();
  if (token)
    config.headers.Authorization = `Bearer ${token}`;
  return config;
});

// 401 → logout + redirect /login
api.interceptors.response.use(
  res => res,
  err => {
    if (err.response?.status === 401) {
      authStore.getState().logout();
      window.location.href = '/login';
    }
    return Promise.reject(err);
  }
);

Ejemplo — customerService.ts

import api from '../lib/api';

export const getCustomers = (params?) =>
  api.get('/api/customers', { params })
     .then(r => r.data);

export const createCustomer = (body) =>
  api.post('/api/customers', body)
     .then(r => r.data);

export const updateCustomer = (id, body) =>
  api.put(`/api/customers/${id}`, body)
     .then(r => r.data);

export const disableCustomer = (id) =>
  api.patch(`/api/customers/${id}/disable`)
     .then(r => r.data);

Cómo agregar un nuevo caso de uso

Los handlers se registran automáticamente — no hay que tocar Program.cs ni DependencyInjection.

1. Command (Application layer)

// ERP.Application/Modules/Ventas/
//   UseCases/CreateFactura/
public record CreateFacturaCommand(
    Guid ClienteId,
    List<LineaInput> Lineas
);

2. Handler (Application layer)

public sealed class CreateFacturaHandler
{
  public async Task<Result<FacturaDto>>
    HandleAsync(CreateFacturaCommand cmd, CancellationToken ct)
  {
    // validar → crear → guardar → auditar
    return Result<FacturaDto>.Success(dto);
  }
}

3. Endpoint (API layer)

[HttpPost]
[Authorize(Policy = "perm:ventas.facturas.create")]
public async Task<IActionResult> Create(
  [FromBody] CreateFacturaCommand cmd,
  CancellationToken ct)
{
  var result = await _handler.HandleAsync(cmd, ct);
  return result.IsSuccess
    ? StatusCode(201, new ApiResponse(result.Value))
    : BadRequest(new ApiResponse(result.Error));
}
